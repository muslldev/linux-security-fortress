# Модель угроз

## Область

Модель рассматривает один Rocky Linux 9.9 сервер, которым управляют с Ubuntu Control Node через Ansible и SSH. Это не формальная оценка всей сети.

## Активы

| Актив | Значимость |
|---|---|
| Административный SSH-доступ | Управление сервером |
| Учётная запись `protected` | Удалённое администрирование |
| Приватный SSH-ключ | Подтверждение права доступа |
| Конфигурация ОС и security-сервисов | Определяет фактический hardening |
| Доступность сервера | Необходима для эксплуатации |
| Inventory и Ansible variables | Параметры управления |

## Границы доверия

- Оператор → Ubuntu Control Node.
- Control Node → Managed Node по SSH.
- Ansible → системная конфигурация через become.
- Входящий сетевой трафик → firewall и SSH.

## Сценарии угроз

| Сценарий | Воздействие | Контроль проекта | Остаточный риск |
|---|---|---|---|
| Подбор SSH-пароля | Несанкционированный вход | Password auth отключена; Fail2ban jail | Компрометация ключа |
| SSH-вход под root | Прямой root access | `PermitRootLogin no` | Компрометация sudo-пользователя |
| Подключение с чужого адреса | Атаки на SSH | Source allowlist в firewalld | Ошибка allowlist или другие открытые сервисы |
| Кража приватного ключа | Вход как `protected` | Защита ключа, firewall, ограничение пользователя | Копирование/злоупотребление ключом |
| Изменение настроек | Ослабление защиты | Ansible-managed configuration, SELinux | Изменения вне Ansible, ошибки ролей |
| Ошибка firewall/SSH | Потеря админ-доступа | Snapshot, VM console, сохранение сессии | Ошибка оператора или недоступность консоли |
| Уязвимое ПО | Эксплуатация CVE | DNF security update checks | Не заменяет vulnerability scanning и patch management |

## Предположения

- Control Node находится под контролем администратора.
- Приватный ключ не публикуется.
- `admin_ip` соответствует доверенному адресу.
- Гипервизор и лабораторная сеть не моделируются как отдельные зоны.

## Вне охвата

Физический доступ, firmware, компрометация ядра, lateral movement, SIEM, управление секретами, резервное копирование, disaster recovery и полноценный penetration testing.

## Дальнейшая работа

1. Полный аудит TCP/UDP listeners и firewall services.
2. Проверка необходимости Cockpit и состояния IP forwarding.
3. Отдельный безопасный Fail2ban ban/unban test.
4. Проверка IPv4 и IPv6.
5. CI для Ansible syntax и lint.
