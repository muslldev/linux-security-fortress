# Политика безопасности

## Назначение

Документ фиксирует целевые правила hardening для лабораторного Rocky Linux managed node. Это политика учебного проекта, а не универсальный стандарт.

## SSH

| Контроль | Целевое значение |
|---|---|
| Порт | TCP/2222 |
| `PermitRootLogin` | `no` |
| `PasswordAuthentication` | `no` |
| `PubkeyAuthentication` | `yes` |
| `AllowUsers` | `protected` |

SSH управляется через `/etc/ssh/sshd_config.d/99-security-hardening.conf`. До применения изменений выполняется `sshd -t`. Новый доступ проверяется до закрытия действующей административной сессии.

## Сетевой доступ

- Firewall управляется через firewalld.
- Для зоны `public` целевое значение target — `DROP`.
- SSH TCP/2222 разрешается только с доверенного IPv4-адреса control node.
- Адрес источника задаётся переменной `admin_ip`.
- Разрешённые сервисы зоны и фактические listeners проверяются отдельно.

Не очищать nftables ruleset и не создавать независимые nftables rules поверх firewalld: это может нарушить управление firewall и привести к потере доступа.

## Fail2ban

| Параметр jail `sshd` | Значение |
|---|---|
| Порт | `2222` |
| Backend | `systemd` |
| `maxretry` | `5` |
| `findtime` | `10m` |
| `bantime` | `1h` |
| Action | `firewallcmd-rich-rules` |

Ban/unban тесты разрешены только с отдельного тестового адреса, не совпадающего с адресом администратора. До функционального теста нельзя заявлять, что блокировка end-to-end подтверждена.

## SELinux

- SELinux должен оставаться в режиме `Enforcing`.
- Для SSH TCP/2222 назначается тип `ssh_port_t`.
- Не отключать SELinux для устранения ошибок; сначала диагностировать AVC и контексты.

## Управление изменениями

1. Перед рискованными изменениями создавать snapshot VM.
2. Иметь доступ к консоли VM.
3. Проверять SSH syntax до reload/restart.
4. Не закрывать текущую сессию до проверки нового входа.
5. Не блокировать адрес control node через Fail2ban.
6. Учитывать firewalld и активные зоны при изменении сетевых правил.
